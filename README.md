# 热量计算器（轻食卡）

从 `foodqc-agent` 项目中拆分出来的独立单页应用：热量计算器 + 拍照 AI 识别 + 每日饮食日志。

## 功能

- **拍照 AI 识别**：拍照 / 实时取景 / 相册上传 / 拖拽图片，自动识别多种食物、估算份量，展示热量与蛋白质、脂肪、碳水。
- **条码 / 包装食品**：扫条形码或手输条码查真实营养数据；查不到可让 AI 查询、拍营养成分表让 AI 自动填表，或手动录入。自己添加的数据会永久进入查询库，计算器随使用不断变聪明。
- **结果确认与修正**：逐项修改食物名称（带自动补全）、克数，删除或手动添加；未收录食物按通用热量估算并标注。
- **分享与导出**：系统分享（含结果图）、剪贴板文案兜底、PNG 结果图下载。
- **识别历史**：最近 20 次识别（含缩略图、餐次、营养素），支持重新载入与删除。
- **实时热量计算**：输入食物与份量即实时估算 kcal / kJ，并显示三大营养素、酒精克数与能量占比条，附慢跑消耗换算。
- **智能搭配推荐**：按当前餐次、本餐已记录热量与每日目标，从内置食谱模板中匹配 3 套搭配，可一键记录。
- **餐次记录 / 每日统计 / 历史日志**：早餐、午餐、晚餐、加餐四餐记录，每日目标进度、剩余/超出提示，按日期倒序查看过往明细，日志中展示三大营养素。
- 桌面端拍照视图左右双栏，移动端单栏；四项切换「计算 / 拍照 / 今日 / 历史」。

## 三大营养素、酒精与能量占比

这部分合并自远程仓库早期版本（commit `44136fc`），已适配到新版全部数据链路：

- **计算页结果区**：显示蛋白质 / 脂肪 / 碳水 / 酒精的实际克数、每 100 克数值，以及四段式能量占比条与百分比。
- **换算口径**：蛋白 4、脂肪 9、碳水 4、酒精 7 kcal/g。酒精段仅在酒类出现，内置已人工复核的 `啤酒 / 红酒 / 白酒(52°)` 酒精数据。
- **拍照 AI 识别**：结果页同样展示能量占比；视觉模型可返回 `alcohol` 字段，识别到酒类时计入。
- **条码 / 自定义食品**：Open Food Facts 的 `alcohol_100g`、AI 读表与手动录入表单都有酒精字段，入库后参与计算；食品库、今日日志、按日历史、识别历史均能显示酒精。
- 旧版的营养建议（优质蛋白 / 脂肪偏高 / 高碳水高能量）也一并保留在计算提示里。

## 包装食品与自定义查询库

新增「📦 条码」页，包含扫码查询、手动录入、我的食品库三块。

### 查询链路（按优先级）

1. **我的食品库**：同一条码/名称已录入过，直接命中，不再联网。
2. **Open Food Facts 开放条码库**：`https://world.openfoodfacts.org/api/v2/product/{条码}.json`，免密钥、已实测返回 `Access-Control-Allow-Origin: *`，可浏览器直连。返回真实的 `energy-kcal_100g`、`proteins_100g`、`fat_100g`、`carbohydrates_100g`、品牌与包装图；只有 kJ 时自动按 4.184 换算。
3. **AI 补充查询**：条码库没有时，调用你在「拍照」页配置好的视觉模型，让它按条码回忆该产品的营养信息。**这是模型记忆、不是联网搜索，属于估算值**，界面会用黄色「AI 估算」标签明确标注，并要求你对照包装核对后再入库。模型表示不认识时返回 `unknown`，应用不会替你编数字。
4. **手动录入**：照包装营养成分表填「每 100g 热量 + 蛋白质/脂肪/碳水」，可填条码、品牌、每份克数、别名。也可点「📷 拍营养表自动填」让 AI 读表预填，再由你确认保存。

### 数据会「长大」

保存后的食品在运行时合并进全局 `FOODS` 查询表与 `MACROS` 营养表，因此**即时计算、搜索联想、自动补全、拍照 AI 识别的名称映射、餐次记录**都会自动认得它；顶部「种食物数据」计数同步增长。查询库里的「🧮 计算」可一键跳回计算页。

食品库支持：搜索、编辑、删除、来源标签（手动录入 / Open Food Facts / AI 估算）、添加时间、**导出 JSON 备份**与**导入**（换设备或重装浏览器后恢复）。

> 「永久保存」指保存在本机浏览器的 `localStorage`（key：`qsk_custom_foods_v1`），刷新、关浏览器、重启电脑都还在。**清除浏览器站点数据会丢失，且不同设备/浏览器之间不共享**——这是纯前端单文件的固有限制，请定期用「导出备份」留存 JSON。若要跨设备同步或多人共享，需要后端数据库，当前版本不含。

### 扫码方式与环境

- **📷 扫码**：调用浏览器原生 `BarcodeDetector`（EAN-13 / EAN-8 / UPC / Code128 / QR），需 HTTPS 或 localhost 且浏览器支持；权限被拒、无摄像头、被占用都有对应提示和替代入口。
- **🖼️ 拍包装**：不受原生扫码支持范围限制，用已配置的视觉模型读条码和营养成分表（需 API Key）。
- **手动输入条码**：始终可用，8–14 位数字。

## 识别引擎（真实 AI，不是演示数据）

在「拍照」页 →「⚙️ 识别引擎设置」中选择服务商并填入自己的 API Key。三种模式：

| 服务商 | 接口地址 | 视觉模型 | 是否需要代理 |
| --- | --- | --- | --- |
| **DeepSeek（默认，推荐）** | `https://api.deepseek.com/chat/completions` | `deepseek-flash` | **不需要** |
| 智谱 GLM | 经本地代理 `http://localhost:8787/api/paas/v4/chat/completions` | `glm-4.6v-flash`（免费） | 需要 `glm-proxy.py` |
| 自定义 | 自填 | 自填 | 取决于该接口 |

另保留「本地演示识别」单选，返回**示例数据**、明确标注，仅用于体验交互，不代表真实识别。

### DeepSeek：三步即可用

1. 在 [platform.deepseek.com](https://platform.deepseek.com) 创建 API Key（按量计费）。
2. 打开 `index.html` → 拍照页 → 识别引擎设置，服务商选 **DeepSeek**（默认值），粘贴 Key → 保存设置。
3. 拍一张食物照片，点「开始 AI 识别」。

已用预检请求实测：DeepSeek 接口返回完整 CORS 头（`Access-Control-Allow-Origin` 回显具体 Origin、`Access-Control-Allow-Headers` 含 `authorization,content-type`），对 `Origin: null` 也放行。因此**原则上直接双击打开本地 HTML 文件就能用**，无需代理或静态服务器。个别浏览器对 `file://` 页面另有额外限制，如遇拦截，执行 `python -m http.server 8000` 后访问 `http://localhost:8000/index.html` 即可。

### 智谱 GLM：需要本地代理

智谱 `open.bigmodel.cn` 接口的预检响应不带 `Access-Control-Allow-Origin`，浏览器直连会被 CORS 拦截（已实测）。所以：

1. 在 [bigmodel.cn 控制台 → API Key](https://bigmodel.cn/usercenter/proj-mgmt/apikeys) 获取密钥。
2. 在本文件夹运行（需 Python 3，仅标准库、零依赖）：
   ```bash
   python glm-proxy.py
   ```
   代理只监听 `127.0.0.1:8787`，透明转发到智谱，不保存密钥、不记录照片、透传上游错误码。
3. 页面服务商选 **智谱 GLM**（端点/模型/纯 Base64 选项会自动填好），粘贴 Key → 保存设置 → 识别。识别期间请保持代理终端窗口打开。

> 若改了代理端口（`--port 9000`），需同步把页面接口地址改成对应端口。
> 自定义接口若不支持 CORS，同样需要自行加一层代理。

### 协议差异（已按各家官方文档适配）

- **图片格式**：DeepSeek / OpenAI 兼容接口用完整 `data:image/jpeg;base64,...`；智谱 GLM 要求 `image_url.url` 为**纯 Base64 字符串**（不带前缀），由「纯 Base64 图片」复选框控制。
- **思考模式**：智谱 GLM 默认开启思维链，请求会附 `thinking: {"type":"disabled"}` 以加快识别；DeepSeek 不下发该参数。
- **认证**：两者都是 `Authorization: Bearer <API_KEY>`。
- 图片在浏览器内压缩到长边 1200px 后发送。

## 相机权限与环境

- 移动端「📸 拍照」调用系统相机，由系统处理授权；桌面端走网页实时取景。
- 「🎥 实时取景」使用 `getUserMedia`，需 HTTPS / localhost。权限被拒绝、无摄像头、被占用或环境不安全时，会给出具体原因与替代方案。
- 直接双击打开本地 `index.html`（`file://`）时，实时取景可能不可用，**拍照 / 相册上传不受影响**；DeepSeek 在线识别在 `file://` 下同样可用。
- 识别历史仅保存 260px 缩略图，不保存原图。

## 使用

纯静态单文件、无构建步骤。直接双击 `index.html` 即可；如需网页实时取景，用静态服务器托管，例如 `python -m http.server 8000` 后访问 `http://localhost:8000/index.html`。

## 数据说明

- 饮食记录、每日目标、识别历史、自定义食品库、引擎配置保存在浏览器 `localStorage`；API Key 默认仅保留在当前会话内存中，勾选「在本机记住密钥」才写入 `localStorage`。
- 热量基于《中国食物成分表》常见值整理，三大营养素优先取内置数据表，未收录项按食物类别的能量比例推算，均为**估算值**。
- AI 识别与推荐不构成医疗或营养建议。
